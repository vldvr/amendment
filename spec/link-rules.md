# Правила хвостов ссылок (Редактура)

Версия: черновик, набор правил `version` 1 (формат `format` 1), 2026-11-08.: живые проверки 2026-11-08 и отчёты пользователей.

Спецификация общая для Mac и Windows. Обе платформы обязаны давать одинаковые результаты на `spec/link-cases.tsv` по `spec/link-rules.json`. Эталон — `spec/tools/check-link-rules.py` (только стандартная библиотека Python): `python3 spec/tools/check-link-rules.py`.

## Что делает модуль

Когда в буфер обмена попадает ссылка, скопированная в «делящейся» программе, модуль убирает из неё хвосты и кладёт в буфер чистую ссылку. Работает только на тексте из буфера. Сеть не используется: ничего не раскрываем и не открываем.

## Три класса хвостов

| Класс | В файле | Что делаем | Что показываем |
|---|---|---|---|
| выдаёт тебя | `gives_away` | убираем | карточка |
| следит | `tracks` | убираем | ничего; счётчик +1 |
| нужен для работы | `needed` | не трогаем никогда | ничего |

- **Выдаёт тебя** — значение связано с человеком или его устройством и не меняется от страницы к странице (Instagram `srtk`/`vrfl`, YouTube и Spotify `si`, TikTok `web_id`, X `t`).
- **Следит** — метка источника или кампании, к человеку не привязана (`utm_*`, `fbclid`, `ysclid`, Google `usp`).
- **Нужен для работы** — без него ссылка ведёт не туда: время и ролик YouTube, `resourcekey` Google, `node-id` Figma, поисковые запросы, всё, чего правила не знают.

Класс результата — высший из убранных: `gives_away` > `tracks` > `none` (ничего не убрали). Показ: `gives_away` → `card`, `tracks` → `silent`, `none` → `none`.

Счётчик «убрано хвостов» растёт на один за одно копирование, а не за каждый параметр.

**Диски.** Владелец Google Диска виден на странице без всякого хвоста, поэтому для дисков это считается допустимым. Карточки для дисков нет. У Google остаётся только `usp` (следит).

## Формат `link-rules.json`

```
format          1. Структура файла. Клиент, не знающий этот формат, правила не берёт.
version         целое, растёт при каждой раздаче. Клиент берёт файл только если version больше текущего.
updated         дата, ГГГГ-ММ-ДД
sharing_apps    «делящиеся» программы (ниже)
short_links     короткие ссылки: не трогаем целиком
global.params   правила для любого домена
domains         правила по доменам
```

В сборке лежит вшитая копия (запасной вариант без сети); сервер раздаёт более свежую. Битый или неизвестного формата файл с сервера отбрасывается молча, остаётся прежний.

## Раздача

Адрес: `https://raw.githubusercontent.com/vldvr/redakciya-rules/main/link-rules.json`. Это отдельный публичный репозиторий, в нём только этот файл и README; основной репозиторий приватный. Файл туда кладёт `spec/tools/publish-rules.sh` после проверки эталоном. Пушит человек, сам скрипт ничего не отправляет.

Клиент (Mac и Windows одинаково):

- **Когда.** Через минуту после запуска, потом раз в 24 часа. Пауза Редактуры проверку не останавливает.
- **Запрос.** Обычный GET по HTTPS, без cookies, кэша и данных о человеке. User-Agent — `Redakciya/<версия программы>`. Таймаут 15 с, ответ больше 1 МБ отбрасывается.
- **Приём.** Файл берётся, только если код ответа 200, он проходит ту же проверку, что вшитая копия (`format` = 1, структура, регулярные выражения), и `version` больше текущей. Иначе молча остаётся прежний набор; в журнал пишется только причина, без содержимого.
- **Кэш.** Принятый файл байт в байт пишется в свою папку: Mac — `~/Library/Application Support/Redakciya/link-rules.json`, Windows — `%APPDATA%\Redakciya\link-rules.json`. Запись атомарная, через временный файл. При запуске кэш берётся, если он проходит проверку и его `version` больше вшитой; иначе используется вшитая копия, а кэш не трогается.
- **Откат.** Если раздали плохие правила, публикуется исправленный файл с ещё большей `version`. Уменьшать `version` нельзя: клиенты его не возьмут.

Запись параметра:

```
name | prefix   точное имя или начало имени (ровно одно из двух), без учёта регистра
values          необязательно: правило действует, только если значение (после раскодирования) равно одному из списка, с учётом регистра
class           needed | tracks | gives_away
confidence      high | medium | low: насколько проверено (в алгоритме не участвует)
note            зачем
```

Запись домена: `id`, `hosts` (без `www.`, подходят и поддомены), `mode`, `unknown_class` (только для `allow`), `params`.

- **`deny`** (чёрный список) — убирается только то, что названо в `params` или в `global`; неизвестное остаётся. Это режим по умолчанию: ошибка в правиле не ломает ссылку.
- **`allow`** (белый список) — остаётся только то, что в `params` как `needed`; всё остальное убирается, неизвестное — с классом `unknown_class`. Нужен там, где сервис меняет имя параметра, а значение держит постоянным. Сейчас так только у Instagram (`igshid` → `igsh` → `igsi` → `srtk` → `vrfl`).

## Алгоритм (общий для обеих платформ)

Вход — одна строка. Выход — строка, класс, имена убранных параметров.

1. **Это одна http(s)-ссылка?** Строка не содержит пробелов и начинается с `http://` или `https://` (регистр схемы не важен, сравнение только латиницей: `httpſ://` с U+017F — не ссылка). Иначе вернуть как есть. Текст с ссылкой внутри, ссылки без схемы, `mailto:`, `file:` не трогаем.
2. **Разбор.** Сначала отрезать фрагмент по первому `#`, потом запрос по первому `?`. Хост — часть до первого `/`, без `user@` (берётся всё после последней `@`), без `:порт`, строчными, без точки в конце. Пустой хост — вернуть как есть.
3. **Короткая ссылка?** Если хост подходит под запись из `short_links` (равен или оканчивается на `.` + хост) и путь начинается с `path_prefix` (если он есть) — вернуть как есть, целиком, даже с `utm_`.
4. **Правило домена.** Среди `domains[].hosts` взять самый длинный подходящий хост. `notyoutube.com`, `youtube.com.example.org` и `www.youtube.com@example.com` не подходят: сравнение идёт по границе точки и только с хостом.
5. **Параметры запроса.** Разбить по `&`. Пустые сегменты пропускать. Имя — до первого `=`, раскодировать (`%XX`, UTF-8) и перевести в нижний регистр; значение — после первого `=`, раскодировать. Классифицировать по порядку:
   1. записи `params` домена (первая подошедшая);
   2. записи `global.params`;
   3. если режим домена `allow` — `unknown_class`;
   4. иначе — оставить.

   Класс `needed` — оставить. `tracks` и `gives_away` — убрать.
6. **Фрагмент** (то, что после `#`). Разбирается, только если он похож на параметры: после отделения `:~:…` (директива текста страницы) остаётся непустое, каждый сегмент содержит `=`, нет `/` и `?`. Тогда те же шаги 5.1–5.2, но **без** пункта 5.3: неизвестное во фрагменте остаётся даже на `allow`-домене. Директива `:~:…` не трогается. Якорь `#comments`, маршрут SPA `#/page?x=1`, `#gid=123` и `#t=30` остаются.
7. **Сборка.** Если ничего не убрано — вернуть вход без единого изменения. Иначе: схема, хост и путь как были (запись хоста и порт не меняются), оставшиеся сегменты запроса побайтно как в исходнике и в прежнем порядке, через `&`; пустой запрос — без `?`; пустой фрагмент после убранного — без `#`; исходный пустой `#` при убранном запросе сохраняется.

Свойство: результат, поданный на вход снова, не меняется. Эталон проверяет это на каждом случае.

## Правила по сервисам

Уверенность указана у каждого правила в `link-rules.json`.

| Домен | Режим | Убираем | Не трогаем |
|---|---|---|---|
| `instagram.com` | allow | `igsh`, `igshid`, `igsi`, `srtk`, `vrfl` — `gives_away`; любое другое имя — `gives_away`; `utm_*` — `tracks` | — (пока ничего, см. «Не решено») |
| `youtube.com`, `youtu.be` | deny | `si` — `gives_away` | `t`, `v`, `list` |
| `spotify.com` | deny | `si`, `dlsi` — `gives_away` | остальное, в том числе `nd` |
| `tiktok.com` | deny | `web_id` — `gives_away`; `is_from_webapp`, `sender_device`, `_t`, `_r` — `tracks` | остальное |
| `x.com`, `twitter.com` | deny | `t` — `gives_away`; `s` со значением 19, 20 или 46 — `tracks` | `s` с другим значением, `q`, `src` |
| `drive.google.com`, `docs.google.com` | deny | `usp` со значением `sharing` или `drive_link` — `tracks` | `resourcekey`, `id`, `gid` в фрагменте, `usp` с другим значением |
| `figma.com` | deny | — | `node-id` |
| `wildberries.ru` | deny | `targetUrl=SN` — `tracks` | остальное |
| любой домен | — | `utm_*`, `fbclid`, `ysclid` — `tracks` | всё остальное, включая поисковые запросы (`q`, `text`) |

Instagram — единственный `allow`-домен: правило по имени там не держится (имя меняется за месяцы, значение остаётся). Режим `allow` действует на весь домен, поэтому `hl`, `next` и подобные тоже уходят; сейчас это приемлемо, потому что ссылки на публикации не требуют параметров.

**Российские правила.**
- `ysclid` — общее правило: Яндекс ставит его на сторонние сайты при переходе из выдачи.
- Яндекс Диск (`disk.yandex.ru/i/…`, `/d/…`, `yadi.sk`): хвоста нет, карточки нет. Общее правило `utm_*` на нём работает, как на любом домене. Владелец виден на странице, и это решено не трогать.
- Wildberries: `targetUrl=SN`. Ozon: только общие метки, `at` и `sh` не трогаем (смысл неизвестен).
- VK — правил нет (в 1e данных нет).
- `clck.ru` — короткая ссылка.

**Короткие ссылки** (`short_links`): `clck.ru`, `vm.tiktok.com`, `vt.tiktok.com`, `ozon.ru/t/…`. В v1 их не раскрываем: раскрытие — запрос к сервису, он засчитает переход и увидит нас. Ссылку не меняем ни на байт, карточки нет. `youtu.be` не короткая в этом смысле: идентификатор ролика лежит в пути, хвост убирается локально.

## «Делящаяся» программа

Ссылку обрабатываем, только если в момент копирования активное окно принадлежит программе из `sharing_apps`: браузеры, Telegram, Discord, Spotify. Ссылка из терминала, IDE, Excel и любой другой программы не трогается, даже если выглядит как ссылка с `si=`.

- Определяем по активному окну **в момент** копирования (смена содержимого буфера), а не на момент проверки.
- Mac — по bundle id, Windows — по имени exe. Список лежит в правилах и раздаётся с сервера, чтобы новые браузеры добавлять без сборки.
- Telegram на Mac бывает двух видов: нативный `ru.keepcoder.Telegram` и Qt-шный `org.telegram.desktop`. Оба в списке.
- Пользователь может исключить программу: ссылки из неё не трогаются. Список исключений хранится на устройстве, наружу не уходит.

## «Вернуть хвост»

- Действие в карточке `gives_away` и в статусе счётчика для `tracks`: кладёт в буфер исходную строку, как она была скопирована.
- Работает, пока в буфере лежит наша чистая строка. Если человек уже скопировал что-то другое, действие недоступно: чужой буфер не перезаписываем.
- Исходная строка хранится только в памяти и не пишется на диск (в ней может быть метка отправителя).
- Возврат не отключает правила: следующая ссылка очистится снова. Постоянное отключение — исключение по программе.

## Формулировки

Хвост в адресной строке часто чужой: его поставил тот, кто прислал ссылку, а не сам человек. Поэтому:

- не писать «твой аккаунт» и «ты поделился»: неизвестно, чья метка;
- не писать «получатель увидит твоё имя»: в 1e без входа получатель отправителя не видел нигде; метка связывает ссылку с отправителем **для сервиса**;
- не пугать: сухо, по делу, без щитов и замков.

Черновые тексты (окончательные — в `design/`):

| Где | Текст |
|---|---|
| Заголовок карточки | В ссылке метка аккаунта |
| Тело карточки | Она связывает ссылку с тем, кто поделился. Убрана. |
| Если из `removed` есть и `tracks` | Ещё убраны метки перехода: N. |
| Действие | Вернуть хвост |
| Тихий случай (статус) | Убрано хвостов: N |

## Не решено

Этих правил нет в 1e или в них не уверены. В `link-rules.json` их нет; где случай уже записан в `link-cases.tsv` (помечен «Не решено»), он фиксирует «не трогаем».

1. **Instagram `img_index`** (номер слайда карусели). Режим `allow` его сейчас убирает, а он нужен для работы. Добавить как `needed`? В 1e его нет.
2. **Instagram `unknown_class`.** Я поставил `gives_away` для любого незнакомого имени, чтобы новое переименование хвоста всё равно давало карточку. Цена: ложная карточка на безобидном параметре. Подтвердить.
3. **YouTube `is`** (по одной заметке с начала 2026, вживую не встречался).
4. **Spotify `nd`** (дописывается вместе с `dlsi`, смысл не известен) и класс `dlsi` (выбран `gives_away` по описанию «метка визита получателя»).
5. **Figma `t`, Notion `pvs`** — в 1e класс не определён.
6. **Google `usp`** с другими значениями (`drive_web`, `share_link`, `sf_link`, `pp_url`) — не трогаем, пока не проверены.
7. **Ozon `at`, `sh`, `asb`** и **Wildberries `targetUrl`** с другими значениями (кроме `SN`).
8. **VK.** Ни одного правила: данных в 1e нет. Нужны образцы ссылок `vk.com` из «Поделиться» и адресной строки.
9. **Общие метки вне 1e:** `gclid`, `yclid`, `msclkid`, `mc_cid`, `mc_eid`, `_openstat`. Известны, но не проверялись в этом проекте. Добавлять в `global`?
10. **Короткие ссылки:** не трогаем совсем (как сейчас) или показываем подпись «короткая ссылка, хвост не виден»?
11. **«Вернуть хвост»:** как долго доступно (до следующего копирования или ограничено временем карточки).
12. **Список программ:** bundle id и имена exe, кроме Telegram, взяты по общеизвестным, вживую не сверялись; Arc на Windows не внесён.
13. **Несколько ссылок в буфере и текст со ссылкой внутри** в v1 не разбираются. Нужно ли в v2?
14. **Исключения по сайтам** (в плане только по программам).
