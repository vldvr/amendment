# Код выдачи

Версия: черновик v2, 2026-11-08. Проверен на Mac и Windows, включая живую отправку через Telegram для macOS 13.1. v2: грамматика знака номера дополнена тем, как его пишет `Windows.Media.Ocr`.

Эта спецификация общая для Mac и Windows. Обе платформы обязаны давать одинаковые результаты на `spec/issue-code-cases.tsv`. Эталонная проверка — `spec/tools/check-issue-code.py` (только стандартная библиотека Python).

## Зачем

На каждой копии из Перепечатки стоит короткий код выдачи. В журнале выдачи у кода записано, какой документ, кому и когда выдан. Если копия всплывёт где-то ещё, человек бросает её в Редакцию, и по коду находится запись.

Код — метка, а не секрет. Он ничего не защищает и не доказывает, только помогает вспомнить, кому отдавали копию.

## Код

- **4 знака из алфавита** `2345679ABCEHJKMPRSTUVWXY` (24 знака). Нет 0/O, 1/I/L. Из пар, которые путает OCR, оставлен один знак: нет 8 (её читают вместо B), N (M), Z (7), F (E), G (6), Q и D (их читают как O).
- **Случайный**, из криптографического генератора.
- **Отличается от каждого кода в журнале минимум в двух позициях.** Тогда ни одна ошибка OCR в одном знаке не превращает код в чужой. Ёмкость с этим правилом — до 24³ = 13 824 кодов; если новый код не находится, это ошибка, а не повод ослабить правило.
- **На копии пишется** `№ H7RK`: знак номера, пробел, код. Моноширинный жирный шрифт.

Журнал выдачи — `reprint.md`, «Журнал выдач». Правило двух позиций действует на весь журнал владельца.

## Вёрстка кода на копии

Копия — оригинал и жёлтая полоса под ним. Обозначения: `w` — ширина оригинала, `d` — высота, `L = max(w, d)`, `k = w / 1600`. Все размеры — в пикселях копии.

| Что | Размер |
|---|---|
| кегль кода | `max(54k, 0,03 L)` |
| кегль узора | `max(40k, 0,022 L)` |
| высота полосы | `max(0,13 d, 1,9 × кегль кода)` |
| поля полосы `pad` | `48k` |

- **Код** — справа в полосе, по центру её высоты, отступ `pad` от правого края.
- **Строка** «Для: <назначение>, <дд.мм.гггг>» — слева, жирная, кегль `54k`. Если она не помещается в `w − 3 pad − ширина кода`, кегль уменьшается. Под ней «Копия. Другим лицам не передаётся.»: кегль — 30/54 строки, тушь 75 %.
- **Узор** — «для: <назначение>, № <код>» под углом 20° по всему документу (не по полосе), тушь `#16181B` с прозрачностью 0,14. Шаг строк `150 s`, шаг надписей `900 s`, каждая вторая строка сдвинута на `450 s`, где `s` = кегль узора / 40.
- **Цвета:** полоса `#FFC21A`, тушь `#16181B`.

**Почему так.** OCR надёжно опознаёт код от кегля 12 px в готовой картинке. Telegram отдаёт фото с длинной стороной 1280 px и JPEG Q75. Формула держит код не меньше 14 px на всех проверенных путях, включая превью 800 px и скриншот чата с телефона. Первая вёрстка (кегль только от ширины) у скриншота телефона опускалась до 7 px.

Шрифты — системные: на Mac SF и SF Mono. На Windows не выбраны; порог перемерен только на копиях, свёрстанных на Mac.

**Как читать на Windows.** `Windows.Media.Ocr` целую копию читает хуже Vision и иногда теряет код даже крупным кеглем. Поэтому сначала найти полосу по цвету `#FFC21A`, вырезать её, увеличить вдвое и читать движком `ru`: так код опознаётся от 11 px. Если полосы нет — вся картинка ×2, потом узор.

## Чтение кода

На входе — строки OCR (до трёх вариантов на строку, каждый вариант — отдельная строка) и коды журнала. На выходе — один код журнала, «неоднозначно» со списком кандидатов или «не опознан».

### 1. Нормализация строки

Заглавные буквы. Кириллические двойники → латиница: А→A, В→B, Е→E, К→K, М→M, Н→H, О→O, Р→P, С→C, Т→T, У→Y, Х→X, З→3, Б→6.

### 2. Слова

- **Слово после №:**
  ```
  (?<![\p{L}\p{N}])(?:№\s*|N[º°O0Q2!':]\.?\s*|N\.?\s+|H[:']\s*)([0-9A-Z]{4}|[0-9A-Z]{2} [0-9A-Z]{2})(?![\p{L}\p{N}])
  ```
  Берётся группа, пробел внутри убирается. Vision пишет знак номера как «№», «Nº», «N°», «No»; `Windows.Media.Ocr` — как «N2», «N!», «N'», «Н:», «Н'» (кириллическая Н после нормализации — `H`) или теряет его. OCR иногда разрывает код пробелом.

  Голая `N` — знак, только если за ней пробел. Иначе мусор английского движка вроде `nmuaM` («лицам») стал бы «№ MUAM», и с одной прощённой ошибкой такое слово находило бы соседний код примерно в 8 % случаев при журнале в 300 кодов.
- **Любое слово:** `(?<![\p{L}\p{N}])[0-9A-Z]{4}(?![\p{L}\p{N}])`.

### 3. Двойники внутри слова

В каждом найденном слове: 8→B, N→M, Z→7, F→E, G→6. Только внутри слова, не во всей строке: иначе «Nº» станет «Mº» и знак номера потеряется.

### 4. Поиск в журнале

**Неразобранный знак** — O, 0, Q или D: таких знаков в кодах нет, значит, OCR не разобрал букву.

1. **Точное совпадение:**
   - любое слово без неразобранных знаков совпадает с кодом;
   - или слово после № с ровно одним неразобранным знаком совпадает с кодом во всех остальных позициях.

   Если подошёл один код — он и есть ответ. Если несколько — остаются те, что совпали со словом после №. Остался один — ответ, иначе «неоднозначно».
2. **Одна ошибка** — только если точных совпадений нет: слово после № без неразобранных знаков отличается от кода ровно в одной позиции. Один код — ответ, несколько — «неоднозначно».
3. Иначе — «не опознан».

**Чего нельзя:**
- Допускать ошибку или неразобранный знак в словах не после №. Год «2026» из даты совпал бы с каждым кодом вида `2?26`, а слово `PETR` из машиночитаемой строки паспорта при журнале в 300 кодов находит соседа с одной ошибкой в 4 % случаев.
- Выбирать из нескольких кандидатов наугад. Хуже непрочитанного кода — копия, опознанная как выданная другому человеку.

Точное совпадение со словом не после № оставлено на случай, когда OCR потерял знак номера. Цена — шанс около 300 / 24⁴ ≈ 0,1 % на каждое случайное 4-знаковое слово документа при журнале в 300 кодов.

### Ввод руками

Код, набранный человеком в поиске, проходит ту же нормализацию и ищется как слово после №: регистр и раскладка не важны, одна опечатка прощается.

## Тестовые случаи

`spec/issue-code-cases.tsv`, колонки:

| Колонка | Что |
|---|---|
| `id` | имя случая |
| `journal` | коды журнала через запятую |
| `lines` | строки OCR через ` \| ` |
| `expect` | код; `—` — не опознан; `?` — неоднозначно |
| `how` | `exact` или `fuzzy` (одна ошибка); для `—` и `?` — `—` |
| `note` | зачем случай |

Проверка: `python3 spec/tools/check-issue-code.py` — 0 при успехе, иначе список расхождений.

## Не решено

- Правило двух позиций при одновременной выдаче с нескольких устройств.
- Шрифт кода на Windows и порог на копиях, свёрстанных там.
- Тон узора на тёмных участках: сейчас на чёрных полях скриншота узор не виден.
- Как в интерфейсе показывать «неоднозначно».
