# Формат архива

Версия: черновик v1, 2026-11-08. Проверен на Mac и Windows, обе стороны сверены с эталонным `age` 1.3.2.

Эта спецификация общая для Mac и Windows. Обе платформы обязаны давать одинаковые результаты на векторах ниже.

## Принципы

- Документ в архиве — обычный файл age v1 ([age-encryption.org/v1](https://age-encryption.org/v1)). Своё в формате только одно: блок ключа устройства в заголовке.
- Ключ устройства не покидает железо: Secure Enclave на Mac, TPM на Windows. Каждое открытие подтверждает человек: Touch ID или пароль, Windows Hello.
- По 12 словам восстановления документ открывает штатный `age`, без Редакции: `spec/tools/words-to-age-key.py` + `age -d -i`.

## Файл документа

Один документ — один файл `.age`. В заголовке:

1. Блок ключа восстановления: стандартный `X25519` из age.
2. По одному блоку `redakciya-p256` на каждое устройство владельца.

Порядок блоков не важен. Обычный `age` блок `redakciya-p256` пропускает и открывает файл ключом восстановления.

## Блок ключа устройства `redakciya-p256`

```
-> redakciya-p256 <тег> <эфемерный ключ>
<тело>
```

Ключ устройства — P-256, создан в железе, не извлекается. Вычисление ECDH с ним требует присутствия человека.

**Обёртка ключа файла** (16 байт):

1. `E` — новый эфемерный ключ P-256.
2. `share` = `E.public` в сжатом виде SEC 1 (33 байта).
3. `device` = открытый ключ устройства в сжатом виде SEC 1 (33 байта).
4. `shared` = координата x точки ECDH(`E`, `device`), 32 байта.
5. `wrap` = HKDF-SHA256(ikm = `shared`, salt = `share` ‖ `device`, info = `"redakciya/v1/p256"`, 32 байта).
6. `тело` = ChaCha20-Poly1305(ключ `wrap`, nonce из 12 нулевых байт, без AAD, открытый текст = ключ файла): 32 байта.
7. `тег` = base64 первых 4 байт SHA-256(`device`), 6 знаков. `эфемерный ключ` = base64(`share`), 44 знака.

Base64 везде как в age: стандартный алфавит без `=`.

**Снятие обёртки:** блоки с чужим тегом пропускаются без обращения к железу и без запроса подтверждения. Если тег свой, а тело не открылось (совпадение тегов, шанс 1 к 2³²), берётся следующий блок.

На Mac ключ — `SecureEnclave.P256.KeyAgreement` с флагами `.privateKeyUsage` и `.userPresence`, хранится как `dataRepresentation`.

На Windows ключ — ECDH P-256 в Platform Crypto Provider (TPM). Подтверждение привязано к ключу так:

1. Ключ Windows Hello (RSA, `KeyCredentialManager`) подписывает строку `"redakciya/v1/tpm-usage-auth"`: RSASSA-PKCS1-v1_5, SHA-256. Подпись детерминирована.
2. `auth` = SHA-256(подпись), 32 байта — usage authorization ключа в TPM (`PCP_USAGEAUTH`), задаётся при создании.
3. Для ECDH `auth` подставляется заново, то есть каждый раз нужен Hello. Без `auth` TPM ECDH не делает.
4. Сырой секрет CNG (`BCRYPT_KDF_RAW_SECRET`) — little-endian, перед HKDF развернуть в big-endian.

Подписывать через Passport KSP (`MS_NGC_KEY_STORAGE_PROVIDER`) с `NCRYPT_WINDOW_HANDLE_PROPERTY`: WinRT-API не знает окна-владельца, и окно Hello уходит назад. Подпись та же.

## Ключ восстановления

1. `entropy` — 16 случайных байт.
2. `checksum` — старшие 4 бита первого байта SHA-256(`entropy`).
3. 132 бита (`entropy`, затем `checksum`, старший бит первым) режутся на 12 чисел по 11 бит. Каждое число — номер слова в `spec/recovery-words-ru.txt`, считая с нуля.
4. Секретный ключ X25519 = HKDF-SHA256(ikm = `entropy`, salt = `"redakciya/recovery/v1"`, info = `"age-x25519"`, 32 байта).
5. Строка ключа — как у `age-keygen`: Bech32 с префиксом `age-secret-key-`, заглавными (`AGE-SECRET-KEY-1…`). Открытый ключ — `age1…`.

Слова — только запись случайных бит, поэтому медленный KDF не нужен: перебирать 2¹²⁸ вариантов бессмысленно.

**Ввод слов:** регистр не важен, «ё» = «е», достаточно первых четырёх букв (в списке они уникальны). Неверная контрольная сумма — «одно из слов неверно или не на своём месте». Неверный набор проходит контрольную сумму в 1 случае из 16, тогда файл не откроется — сообщение то же.

## Список слов

`spec/recovery-words-ru.txt`: 2048 слов, по алфавиту, по слову в строке.

Требования: 4–8 букв, без «ё», существительное в начальной форме, первые четыре буквы не повторяются, без брендов, болезней, грубых и мрачных слов.

**Вычитан 2026-11-09.** Первый черновик (бренды, болезни, наречия, национальности, редкие слова) заменён: список собран заново из обычных нейтральных существительных (животные, растения, еда, предметы, места, занятия), отобран по требованиям выше и проверен русским словарём macOS; 674 слова из черновика остались. После релиза список не меняется никогда: другое слово под тем же номером ломает чужие ключи восстановления. Векторы выше от списка не зависят: в них номера слов.

## Раскладка

Решено 2026-11-09.

- **Папка.** `~/Редакция/Архив/` (на Windows `%USERPROFILE%\Редакция\Архив\`): видна в Finder и Проводнике, попадает в резервные копии.
- **Документ** — файл `<имя>.age` рядом с оглавлением. `<имя>` — исходное имя файла; если занято, `имя 2.jpg.age`. Внутри — исходные байты файла без изменений.
- **Оглавление** `archive.json` открыто, без шифрования: название, вид, срок действия, дата сдачи, исходное имя, размер. Список документов виден без Touch ID, содержимое — только с ним. Так утренний выпуск может сам напомнить, что паспорт истекает. Если оглавление потеряно, документы всё равно открываются по 12 словам, просто без названий.

```
{
  "format": 1,
  "recovery": "age1…",              открытый ключ восстановления
  "devices": ["<тег>"],             теги ключей устройств, которые есть в файлах
  "documents": [
    {"id": "<uuid>", "file": "Паспорт.jpg.age", "title": "Паспорт РФ", "kind": "passport",
     "expires": "2031-03-01" | null, "added": "2026-11-09T12:00:00Z", "original": "IMG_4021.jpg", "size": 812345}
  ]
}
```

- **Что сдаётся.** Только документы: файл, где детектор нашёл паспорт, СНИЛС, ИНН, полис ОМС, карту или счёт, и то, что человек сдал сам. Обычное старьё Стола остаётся в «Убрано со стола» без шифрования.
- **Оригинал** после сдачи уходит в Корзину, а не стирается: «ничего не удалять автоматически». Перед этим программа проверяет, что файл `.age` записан и его заголовок читается.
- **Открыть** — расшифровать во временную папку программы, показать системной программой, временную копию стереть при выходе и через час. **Вернуть** — расшифровать в Загрузки под исходным именем; запись в Архиве остаётся, пока человек не уберёт её сам.
- **Ключи.** Ключ устройства создаётся при создании Архива; на Mac его `dataRepresentation` лежит файлом в своей папке (`~/Library/Application Support/Redakciya/device-key.bin`): вне Secure Enclave этого Mac он бесполезен, а связка ключей спрашивала бы заново после каждого обновления с подписью ad hoc. 12 слов показываются один раз, проверяются вводом двух случайных слов и нигде не хранятся; хранится только открытый ключ восстановления.
- **Второе устройство** в v1 — только по 12 словам: на новом компьютере человек вводит слова, программа открывает каждый документ ключом восстановления и шифрует заново для нового устройства. Синхронизации нет.
- **Срок действия** в v1 вводит человек (вид и название программа предлагает по найденному); распознавание дат — позже.

## Журнал выдач

Решено 2026-11-09: `issues.age` рядом с оглавлением, файл age для тех же получателей, что документы; формат — `reprint.md`, «Журнал выдач». При восстановлении по словам перешифровывается вместе с документами.

## Не решено

- **Сброс ключа устройства.** Сброс Windows Hello или очистка TPM, скорее всего, уничтожают ключ Windows; что тогда видит человек и как переходит к 12 словам. Не проверено.
- **Mac → Windows.** Живой файл с Mac на Windows по словам не открывали (по векторам совпадает).
